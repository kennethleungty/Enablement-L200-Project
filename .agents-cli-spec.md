# Agent Spec: Noogler Onboarding Agent (GEAP L200 Assessment)

## Overview
The **Noogler Onboarding Agent** (`noogler_onboarding_agent`) is an AI assistant built with the Google Agent Development Kit (ADK) on the **Gemini Enterprise Agent Platform (GEAP / Gemini platform)**. It streamlines the onboarding experience for new Google employees ("Nooglers") across three core pillars:
1. **Administrative Onboarding**: Payroll/direct deposit setup, health insurance enrollment, and tax withholding forms.
2. **Tech Logistics**: Hardware ordering (laptop/peripherals) and software/corp access provisioning.
3. **Role-Related Knowledge**: Role-specific expectations, 30-60-90 day onboarding checklists, base readings, and engineering team norms.

The project is architected specifically to demonstrate production-grade agent engineering across all 5 categories of the GEAP L200 Assessment rubric (Tool & Interface Design, Context & Memory, Orchestration & Logic, Observability & Tracing, and Infrastructure & CI/CD) without requiring live cloud deployment to evaluate.

## Architecture & Sub-Agents
We use a clean **4-Agent Coordinator + Specialist Sub-Agents** architecture (`sub_agents=[...]` on the root coordinator) with **Strategic Model Routing** (Flash for fast routing and transactional sub-agents, Pro for deep role-onboarding synthesis and 30-60-90 day planning):

1. **`noogler_onboarding_coordinator` (Root Coordinator Agent — `gemini-2.5-flash` / `gemini-3.8-flash`)**:
   - Greets the Noogler, understands their intent, enforces top-level constitution policies, and routes requests to the appropriate specialist sub-agent(s) via `sub_agents=[admin_onboarding_agent, tech_logistics_agent, role_knowledge_agent]`.
2. **`admin_onboarding_agent` (Specialist Sub-Agent 1 — `gemini-2.5-flash` / `gemini-3.8-flash`)**:
   - Handles salary/payroll direct deposit, tax withholding, and health insurance enrollment.
   - **Tools (2)**:
     - `get_noogler_benefits_and_payroll_status`
     - `submit_payroll_and_benefits_election` (with Human-in-the-Loop confirmation)
3. **`tech_logistics_agent` (Specialist Sub-Agent 2 — `gemini-2.5-flash` / `gemini-3.8-flash`)**:
   - Handles hardware orders (laptops, monitors) and corporate software/access provisioning.
   - **Tools (2)**:
     - `check_tech_equipment_and_access_status`
     - `request_hardware_or_software_provisioning` (with Human-in-the-Loop confirmation for privileged access/hardware)
4. **`role_knowledge_agent` (Specialist Sub-Agent 3 — `gemini-2.5-pro` / `gemini-3.8-pro`)**:
   - Uses a **Pro** model for deep synthesis of role-specific expectations, base readings, engineering team norms, and personalized 30-60-90 day ramp-up plans.
   - **Tools (2)**:
     - `search_role_onboarding_knowledge_base` (backed by persistent knowledge index / Search in Gemini platform)
     - `save_personalized_onboarding_plan` (persists the tailored 30-60-90 day checklist into session/persistent state)

## Example Use Cases
1. **Administrative Setup (with HITL & PII Redaction)**:
   - *Input*: "Hi! I'm a new L4 SWE starting today (SSN 123-45-6789). Can you check my benefits status and enroll me in the PPO health plan with 10% 401k contribution?"
   - *Expected Output*: PII (`123-45-6789`) is redacted in logs/memory before storage; agent calls `get_noogler_benefits_and_payroll_status`, then triggers a Human-in-the-Loop confirmation before executing `submit_payroll_and_benefits_election`.
2. **Tech Logistics Provisioning (with Guided Error Handling)**:
   - *Input*: "I need a MacBook Pro M4 Max and production SSH access enabled for my account."
   - *Expected Output*: Agent checks eligibility via `check_tech_equipment_and_access_status` and calls `request_hardware_or_software_provisioning`. If an invalid package SKU or unapproved access tier is passed, the tool returns structured recovery instructions guiding the LLM to select a valid SKU/prerequisite training.
3. **Role Knowledge & 30-60-90 Day Plan (Persistent Retrieval + Strategic Model Routing)**:
   - *Input*: "What are the base readings and team norms for an L4 Backend SWE, and can you build me a 30-60-90 day onboarding plan?"
   - *Expected Output*: Agent retrieves grounded docs via `search_role_onboarding_knowledge_base` and invokes the Pro-powered `role_onboarding_planner_agent` (`AgentTool`) to produce a structured plan.

## Tools Required
All tools implement **Comprehensive Docstrings**, **Descriptive Naming**, **Explicit Pydantic JSON Schemas** (input/output validation), and **Guided Error Handling** (returning actionable recovery instructions on error rather than raising unhandled exceptions):
1. `get_noogler_benefits_and_payroll_status`: Reads current administrative onboarding status (payroll, tax forms, insurance enrollment) for a Noogler ID.
2. `submit_payroll_and_benefits_election`: Updates health insurance plan or payroll/401k allocation. Protected by ADK `FunctionTool(..., require_confirmation=True)` Human-in-the-Loop hook.
3. `check_tech_equipment_and_access_status`: Checks status of assigned laptop orders and corporate software access groups.
4. `request_hardware_or_software_provisioning`: Submits an IT hardware order or software access request. Requires HITL confirmation for high-cost hardware or privileged access tiers.
5. `search_role_onboarding_knowledge_base`: Queries the persistent role knowledge store (with support for Search in Gemini platform / local vector store fallback) for role expectations, base readings, and team norms.
6. `AgentTool(role_onboarding_planner_agent)`: Delegates complex 30-60-90 day study plan generation to a Pro-model specialist agent.

## Constraints & Safety Rules
1. **System Constitution**: Explicit persona, domain boundaries, and behavioral rules defined in the system prompt—never fabricate HR/benefits policies or bypass IT security approvals.
2. **Runner-Wide Safety & Policy Plugin (`OnboardingGuardrailPlugin`)**: Implements ADK `BasePlugin` (`before_model_callback`, `after_model_callback`, `before_tool_callback`) to enforce policy guardrails, block prompt injection / unauthorized policy overrides, and run self-evaluation checks.
3. **PII Redaction**: Active scrubbing of sensitive fields (SSNs, bank account numbers, personal phone numbers, API tokens) in both structured logs and memory pipelines before persistence (with Cloud DLP / regex fallback).
4. **Human-in-the-Loop (HITL) Gates**: High-stakes state mutations (submitting payroll/benefits changes or requesting privileged software access) require explicit human confirmation before execution.
5. **Secret Management**: Zero hardcoded API keys or credentials; secrets are fetched via Google Cloud Secret Manager (`google-cloud-secret-manager`) with clean environment variable fallback for local evaluation.

## Success Criteria
1. **Tool & Interface Design**: 100% of tools have full Google-style docstrings, descriptive verb-noun names, Pydantic input/output schemas, and guided error dictionaries (`status`, `error_code`, `recovery_instructions`).
2. **Context & Memory**: `App` configures `EventsCompactionConfig` (`token_threshold`, `event_retention_size`) and `ContextCacheConfig`; persistent session/knowledge state and non-blocking async memory consolidation (`asyncio.create_task` in `after_agent_callback`) are active and verified by unit tests.
3. **Orchestration & Logic**: Root agent + `AgentTool` / sequential workflow demonstrates multi-agent orchestration, Flash-to-Pro strategic model routing, `BasePlugin` guardrails, and `require_confirmation` HITL hooks.
4. **Observability & Tracing**: Structured JSON logger outputs both `INTENT` (in `before_tool_callback` / `before_agent_callback`) and `OUTCOME` (in `after_tool_callback` / `after_agent_callback`), links OpenTelemetry trace/span IDs, and redacts PII patterns with 100% pass rate on redaction tests.
5. **Infrastructure & CI/CD**: `agents-cli eval run` executes against the golden evaluation dataset (`tests/eval/datasets/`) and `eval_config.yaml` with target threshold >= 0.80; Terraform IaC (`infra/terraform/`) and CI/CD configs are present and documented.
